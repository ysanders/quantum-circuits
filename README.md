# Quantum circuits

A personal compiler front end for describing quantum computations with small,
immutable Python values. The aim is to preserve useful mathematical structure
while making implementation choices explicit. Ordinary Python functions build
program descriptions; later consumers inspect, transform, analyse, or lower them.

The completed foundation is exact single-qubit Clifford+T algebra and local
sequence composition. **CZ and CCZ are next: their algebra and integration with
normalisation have not yet been implemented.** Basic `CZGate` and `CCZGate`
nodes already exist as scaffolding: they validate and canonicalise their wire
arguments, and the test oracle knows their matrices. At present, `seq` treats
them as boundaries; it neither cancels them nor simplifies through them.

## The model

The central distinction is between an operator value and its application in a
program. An operator describes a linear map independently of qubit names. A gate
attaches that operator to a wire. A sequence composes those applications.

| Value | Responsibility |
| --- | --- |
| `SingleQubitClifford` | Supporting exact algebra for the 192 matrices generated by H and S, including discrete global phases |
| `SingleQubitOperator` | A canonical exact Clifford+T linear operator on one qubit |
| `Qubit` | A wire identified by its string name |
| `Gate` | An operator applied to a named wire |
| `Seq` | A sequence remaining after local normalisation |

All these values are frozen, slotted dataclasses. Equality and hashing follow
from their stored fields. Constructors return inspectable data; they do not
execute a quantum computation. The same operator can be reused on many wires.

### Operator values

`op` accepts gate words, existing operators, and supporting Clifford values.
The public constants `I`, `X`, `Y`, `Z`, `H`, `S`, and `T` are all
`SingleQubitOperator` values. Strings use conventional gate matrices and execute
left to right; whitespace is ignored.

```python
from quantum_circuits import H, I, S, T, op

assert op('HTH') == op(H, T, H)
assert op('TT') == S
assert op('HS') == S @ H
assert T.inverse() @ T == I
assert T ** 8 == I
```

`@` uses matrix order: its right operand acts first. `op` uses execution order.
Both produce canonical values immediately.

Internally, an operator stores one initial Clifford and a string of axis labels.
For example, `axes='xyz'` means apply the initial Clifford, then `T_x`, `T_y`,
and `T_z`. With products written in matrix order,

- `T_x = H T H`;
- `T_y = S H T H S^-1`;
- `T_z = T`.

Neighbouring labels differ. This normal form is unique for each exact
single-qubit Clifford+T operator, so different specifications of the same
operator compare equal and hash equally. Ordinary Python hash collisions remain
possible; equality resolves them.

Global phase is part of the operator. For example, `op(phase=1)` is
`exp(i*pi/4) * I`, and is distinct from `I`. Retaining phase matters when an
operator is later placed under coherent control. Arithmetic and normalisation
use exact finite tables, without floating-point decisions.

```python
u = op('HTSHT')
assert u.inverse() @ u == I
assert not u.is_clifford
assert not op(phase=1).is_identity

word = ''.join(u.iter_gates())
assert op(word) == u
assert word.count('T') == u.t_count
```

`t_count` is the minimal T-count for the isolated exact single-qubit operator.
`iter_gates()` lazily emits an exact H/S/T decomposition in execution order,
including phase. Its Clifford count need not be minimal. This is exact lowering;
approximating arbitrary rotations remains future work.

### Applying operators to wires

`Qubit('q')` identifies the wire named q. Equal names mean the same wire; callers
choose fresh names when necessary. `Gate(op, targ)` applies an operator to a
wire, while `gate(value, targ)` additionally accepts a word.

```python
from quantum_circuits import Gate, Qubit, gate

q, r = Qubit('q'), Qubit('r')
assert gate('HTH', q) == Gate(op('HTH'), q)
assert gate(H, q) != gate(H, r)
assert gate(H, q).qubits == frozenset((q,))
```

A stored Gate can represent a whole single-qubit stretch. Lowering expands its
operator when individual instructions are needed.

### Composing a program

Use `seq(*parts)` in execution order. It flattens child sequences, combines
adjacent single-qubit gates on the same wire, and removes exact identities.
An empty result is `Seq(())`; a singleton becomes its child.

```python
from quantum_circuits import Seq, seq

assert seq(gate(T, q), gate(T, q)) == gate(S, q)
assert seq(gate(H, q), gate(T, q), gate(H, q)) == gate('HTH', q)
assert seq(gate(H, q), gate(H, q)) == Seq(())
assert seq(gate(op(phase=1), q)) == gate(op(phase=1), q)

body = seq(gate(H, q), gate(S, r))
assert body.qubits == frozenset((q, r))
```

Operations on different wires retain their order. The current constructor does
not commute gates or perform general multi-qubit optimisation. Consequently,
single-qubit operator equality is mathematical equality, while circuit equality
is structural equality after the implemented local reductions.

Every node has a computed `.qubits` property. It reports wires referenced by the
stored body, not ownership or a declared interface. A cancelled H-H pair has
an empty referenced-wire set. A future fragment contract may still declare
that wire as a parameter.

Abstraction stays in ordinary Python for now:

```python
def in_h_basis(make_body, target):
    return seq(gate(H, target), make_body(target), gate(H, target))

assert in_h_basis(lambda t: gate(T, t), q) == gate('HTH', q)
```

Functions can accept other constructors and return composed descriptions.
Named fragments and runtime branching will require explicit nodes when added.

## Implementation status and direction

| Area | Status |
| --- | --- |
| Exact Clifford and canonical single-qubit Clifford+T algebra | Implemented, including composition, inversion, integer powers, and exact lowering |
| Named wires and local sequence normalisation | Implemented |
| CZ and CCZ | Node scaffolding only; completing their semantics, algebraic interfaces, and simplification rules is next |
| Contracts, named fragments, repetition, measurement, classical control | Planned |
| Arbitrary-rotation synthesis, resource analysis, backend export | Planned |

The intended downstream vocabulary is single-qubit Cliffords, T, CZ, and CCZ.
This project is responsible for decomposition to that vocabulary; downstream
work will handle routing and magic-state factory selection. Canonical local
operators keep equivalent implementations comparable without forcing every
consumer to inspect a raw gate word.

The broader goal is to build algorithms against mathematical contracts and
choose implementations separately. Once the entangling-gate foundation is in
place, the next semantic milestone is interchangeable coherent and measured
cleanup of a temporary AND, followed by arithmetic using that contract.

## Running the project

Python 3.10 or later is required. There are no runtime or test dependencies
beyond the standard library. From the project root:

```sh
python3.14 -m examples.basic
python3.14 -m unittest discover -v
python3.14 tools/generate_clifford_tables.py --check
```

These commands use the available Python 3.14 interpreter. Another Python 3.10+
interpreter is suitable; on this Mac, bare `python3` in the execution environment
currently selects Python 3.9 and cannot run the project.

An editable installation is optional, for importing from another project:

```sh
python3.14 -m pip install -e .
```

The tests check exact phases, canonicalisation, inverses and decompositions,
including exact matrix uniqueness across 8,832 bounded canonical values and
all 36,864 Clifford products. These finite checks supplement the mathematical
normal-form result; they are not a proof for arbitrary word lengths.
